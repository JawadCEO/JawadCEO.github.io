Research

Accepted for publication · MDPI

Detecting Race Conditions in FHIR-Based Healthcare Interoperability: A Formal Graph-Theoretic Approach

Concurrency · distributed systems

Jawad Mohammed, Gahangir Hossain · University of North Texas

Hospital systems read and write the same patient records through FHIR APIs at the same time, and FHIR defines no locking. A lab can update an allergy record while the EHR approves a prescription from the old version, so each system acts correctly and the patient still gets a contraindicated drug.

I modelled every client and record as a graph, the FHIR Resource Access Graph (FRAG), where a race condition becomes a pattern in that graph. I defined three race types with soundness and completeness proofs, and built a three-pass detector.

FHIR server→audit log→FRAG detector→race alerts
  • Python
  • NetworkX
  • Graph theory
  • Formal methods
  • HL7 FHIR R4
  • 90.0% F1under concurrent access, against 25.5% for a time-window baseline
  • +64.5 ptsF1 gain over the baseline across all three race types
  • 250,000events processed with near-linear scaling on a single core
  • 2 modesbatch audit, or streaming through Kafka for near-real-time alerts

Code and simulation on GitHub

Evaluated on 1,500 synthetic FHIR R4 transaction logs with injected races, not a live clinical deployment.
